## 一、网站打不开 / 进不去

### 情况 1：网页根本打不开（一片空白）

1. **确认软件在运行**：
   - 一键启动版：打开终端，跑 `docker ps`，看 4 个容器是不是都在（cloud-ledger-mysql、redis、backend、frontend）；
   - 自己装的：看后端和前端的窗口是不是还开着。
2. **确认地址对不对**：
   - 一键启动版：浏览器打开 `http://localhost`（注意别加端口）；
   - 自己装的：打开 `http://localhost:5173`。
3. **换浏览器试试**，或者清一下缓存。

---

### 情况 2：网页能打开，但点啥都报错

1. **先看后端起没起**：浏览器打开 `http://localhost:8080`（一键启动版和自己装的都行），要是没反应，就是后端没起来；
2. **看后端启动日志**有没有报错：
   - 数据库连不上 → 看下面"情况 3"；
   - 缓存连不上 → 看下面"情况 4"；
3. **端口被占了** → 看下面"情况 5"。

---

### 情况 3：后端起不来，报"数据库连接失败"

1. 确认 MySQL **服务已启动**；
2. 打开配置文件 `application-dev.yml`，核对：
   - 数据库地址是不是 `localhost`、端口是不是 `3306`；
   - 用户名、密码**跟你自己的 MySQL 一致**；
3. 确认 3306 端口**没被别的程序占用**；
4. 如果是第一次启动报错，可能是账号没权限建库，自己手动建一下 `cloud_ledger` 库。

---

### 情况 4：后端起不来，报"Redis 连不上"或"缓存失败"

1. 确认 Redis **服务已启动**；
2. 打开 `application-dev.yml`，核对：
   - 地址是不是 `localhost`、端口是不是 `6379`；
   - Redis 设了密码的话，把密码填到 `redis.password`；
3. 确认 6379 端口没被占。

---

### 情况 5：报"端口被占用"

8080、5173、3306、6379、80 任一被占都会出问题。

1. 查谁占着：Windows 跑 `netstat -ano | findstr :8080`（Mac/Linux 把 `findstr` 换成 `grep`），看最后那列是进程号；
2. 把占着的程序关掉，或者**换个端口**：
   - 后端端口：改 `application.yml` 里 `server.port`；
   - 前端端口：改 `cloud-ledger-ui/vite.config.js` 里 `server.port`；
   - 一键启动版前端端口：改 `docker-compose.yml` 里 frontend 的端口映射，比如改成 `"8081:80"`，然后访问 `http://localhost:8081`。

---

### 情况 6：一键启动版起不来

1. 确认 Docker 和 Docker Compose **装了并且在运行**；
2. 看具体哪个容器报错：`docker logs cloud-ledger-backend`；
3. 重新构建一次：`docker compose build --no-cache` 然后 `docker compose up -d`；
4. 80 端口被占 → 改 `docker-compose.yml` 的端口映射（见情况 5）。

## 二、登录问题

### 情况 7：登录提示"邮箱或密码错误"

1. 邮箱别拼错（注意大小写）；
2. 密码别记错（注意大小写、有没有多打空格）；
3. 系统不会告诉你具体是哪个错，**对就是对，错就是错**；
4. 还是登不上 → 密码可能真的忘了，**点登录页的"忘记密码"重设一个就行**（见情况 7a~7e）。

---

### 情况 7a：忘记密码，点了"发送验证码"但邮箱没收到

1. 先确认邮箱地址**没填错**；
2. 看看邮箱的**垃圾邮件/广告邮件箱**，说不定被归类了；
3. 等 **60 秒**再重新发一次（系统有冷却时间，防止狂发）；
4. 还是收不到 → 可能是部署时没配好邮件服务（SMTP），找管理员配一下；
5. 如果邮箱本来就没注册过，系统**不会真的发信**（为了防止坏人探测哪些邮箱注册过），但界面上看不出来。

---

### 情况 7b：忘记密码，验证码输错了怎么办

- 验证码输错了**不会作废**（除非连续输错 5 次），可以接着改；
- 但如果提示"验证码已过期"或"错误次数过多"，就得重新发一个了。

---

### 情况 7c：忘记密码，提示"验证码错误"或"验证码已过期"

- **验证码错误**：再仔细核对一下，6 位数字别输错；
- **已过期**：验证码 5 分钟内有效，过期了就得重新发；
- **输错 5 次被锁**：验证码会作废，得重新发一个。

---

### 情况 7d：修改密码时提示"原密码不正确"

1. 原密码就是你**现在正在用的那个密码**，别输成新密码了；
2. 注意大小写、有没有多打空格；
3. 如果真忘了原密码，走"忘记密码"流程（不用登录也能改）。

---

### 情况 7e：修改/重置密码时提示"新密码不能和旧密码相同"

这是安全设计，不能用原来的密码。换一个新的，8-64 位，要有字母也有数字。

---

### 情况 7f：改完密码后被强制退出，重新登录

**这是正常的！** 为了安全：
- 不管是"忘记密码"还是"登录后修改密码"，改完后**所有登录状态自动失效**；
- 所有设备上的登录都会被踢下来；
- 用新密码重新登录就行。

---

### 情况 8：用着用着突然让我重新登录（提示登录过期）

这不是坏了，是登录状态到时间了（30 分钟不动会过期）。
- 直接重新登录就行；
- 如果老是这样，可能你用的网页长时间没动，正常现象。

---

### 情况 9：点了退出，但用旧的登录状态还能进？

**不应该这样**。正常退出后登录状态立刻失效。如果还能用：
1. 清一下浏览器缓存和 Cookie；
2. 关掉浏览器重新打开；
3. 还不行，可能是浏览器记着旧状态，重启浏览器。

## 三、记账问题

### 情况 10：记了笔账，但账户余额没变

多半是用错了地方：
1. **你是不是用了"交易记录"记账？** 那个不绑账户，**本来就不动余额**，是正常的；
2. 想让余额准，要用"账单"来记；
3. 确认账单里**账户选对了**，金额填对了。

---

### 情况 11：金额报错说格式不对

1. 金额必须**大于 0**，不能填 0 或负数；
2. 单位是"元"，可以带小数点，比如 `88.50`；
3. 不要带"￥"符号或"元"字。

---

### 情况 12：日期报错说格式不对

1. 格式必须是 `年-月-日`，用横线分开，比如 `2024-01-15`；
2. 月和日**要补零**，1 月要写 `01` 不能写 `1`；
3. 不要用斜杠 `/`、中文"年月日"、不要带时分秒。

✅ `2024-01-15`
❌ `2024-1-15`、`2024/01/15`、`2024年1月15日`

---

### 情况 13：删了账单，钱没回来

1. 用的是"账单"还是"交易记录"？
   - **账单**：删了会自动补余额。如果没补，刷新一下页面再看；
   - **交易记录**：删了**不会**补余额，因为它本来就没动过余额，是正常的；
2. 如果是账单删了余额真没动，刷新页面、换浏览器试试；还不行就提交反馈。

---

## 四、预算问题

### 情况 14：查预算说"该月暂无预算设置"

1. 确认那个月**真的设过预算**（用"新增预算"设的）；
2. 确认月份填对了：格式 `年-月`，比如 `2024-01`，1 月要写 `01`；
3. 预算金额必须**大于 0**，填 0 或负数会被拒绝。

---

### 情况 15：预算用百分比显示 0，但明明花了钱

1. 这个月**没设预算** → 预算栏是空的、百分比显示 0，正常。先去设预算；
2. 设了预算还是 0，可能是报表缓存没更新，等几分钟刷新看看；
3. 确认你记的支出账单日期，是不是在你看的这个月里。

---

## 五、报表问题

### 情况 16：报表里没数据 / 数据是空的

1. 确认那个月**有账单**（去账单页看看）；
2. 确认用的是"账单"不是"交易记录"——**交易记录不计入报表**；
3. 确认账单日期在你看的那个月内；
4. 报表会缓存一会儿（半小时到 1 小时），刚记完可能要等下，刷新页面。

---

### 情况 17：报表金额显示一长串小数（比如 88.49999999）

这是浏览器显示的问题，不影响实际数据。
- 一般页面会自动显示成两位小数；
- 如果还是一长串，刷新一下页面；
- 实在不行，提交反馈报 bug。

---

### 情况 18：趋势图看不到

1. 确认装了能看图的浏览器（Chrome、Edge 都行）；
2. 确认那几个月**有账单数据**，没记账的月份自然是 0；
3. 刷新页面，或者换浏览器试。

---

## 六、数据丢了 / 想备份

### 情况 19：删了账户，里面的账单也没了，能找回吗？

**找不回来。** 删账户会把里面所有账单一起彻底删掉。如果之前有备份，可以从备份恢复（见情况 20）；没备份就只能重新记。

**提醒**：以后删账户前，先把里面账单导出/截图，或者干脆别删，留着就行。

---

### 情况 20：怎么备份数据？

**目前不能导出成 Excel/PDF，只能整库备份：**

- **自己装的**：
  ```bash
  mysqldump -uroot -p cloud_ledger > backup.sql
  ```
  （会让你输入密码，输完回车）

- **一键启动版**：
  ```bash
  docker exec cloud-ledger-mysql mysqldump -uroot -p<你的密码> cloud_ledger > backup.sql
  ```
  （把 `<你的密码>` 替换为你的真实密码）

### 怎么恢复备份？

- **自己装的**：
  ```bash
  mysql -uroot -p cloud_ledger < backup.sql
  ```

- **一键启动版**：
  ```bash
  docker exec -i cloud-ledger-mysql mysql -uroot -p<你的密码> cloud_ledger < backup.sql
  ```
